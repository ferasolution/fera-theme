# Installation, functional and security verification

Test date: 11 October 2026. Installation: fresh local WordPress Playground, WordPress 7.1.3, PHP 8.3.33, optional free Elementor 4.3.4. The actual theme ZIP was installed using WordPress installation APIs; the theme was not mounted from the preview server. No previous Fera theme/page data was present. An unrelated synthetic page and prior Reading selection were deliberately created to test preservation.

## Executed results

- 44 backend assertions passed: setup idempotence; 11 business pages and 29 applications; old test content/Reading backup; native Elementor document structure and save; five custom widgets; required phone, email, consent and enum validation; array/oversized input rejection; honeypot; nonce validation; anonymous setup rejection; fixed demo-file allowlist; request exception/concurrency recovery; global request allowance, monthly AI reservation and circuit refusal; mocked email acceptance and fixed recipient. Fourteen PHP files passed PHP TOKEN_PARSE. No real AI provider or mailbox was contacted.
- All 40 business/demo URLs returned HTTP 200. The final expanded check verified 86 referenced and bundled image/font/SVG assets returned 200, with no unexpected asset origins. Nested routes are real WordPress pages and survive direct access; browser refresh/persistence workflows were exercised.
- All 11 business pages have one H1, one canonical, one description, unique titles/descriptions, Open Graph/Twitter metadata and parseable JSON-LD. Core XML sitemap parsed and omitted experience routes. Staging robots disallows indexing. Fresh bootstrap returned no-store; missing nonce returned 403. AIOSEO hooks were tested with synthetic plugin context, not an installed production SEO plugin.
- Native POST fallback produced a no-store confirmation containing a fresh nonce and no inquiry data in the URL. Disconnected REST email returned 503 rather than a false success. Browser form retains entered data and provides a clear disconnected error. End-to-end browser success and failure paths were also exercised with a local mail interceptor: acceptance reset the form; failure retained entered details with readable error text. The interceptor was removed and email disabled afterwards. No real messages were sent; inbox delivery was NOT tested.
- All 29 applications were opened and visually reviewed in the browser at desktop width and verified 375x812 mobile width. Mobile views had no page overflow or broken loaded images. Screenshots of each view were reviewed in contact sheets. The 11 business pages were checked at 1280 desktop, 375x812 mobile and 768x1024 tablet dimensions.
- Fourteen record applications: edit/save, refresh persistence and reset checked. Retained CRM/task/inventory applications: edit/reset checked; their temporary state is explicitly disclosed. Awareness answer/feedback/reset, local SEO checks, UTM calculation/unsafe-scheme rejection, retained security and workflow execution/reset were checked. Storefront cart, quantities, calculated total, simulated checkout, persistence/reset; corporate inquiry summary; professional sample booking; restaurant category filtering/cart; three retained website inquiry summaries were checked. These are representative core workflows, not exhaustive testing of every possible record combination.
- Service-page embedded applications worked on all five service pages at 375 pixels, including internal navigation. Preview close/device controls were checked. Frames are sandboxed without same-origin access; embedded persistence may be temporary. Standalone newer applications save non-sensitive demo data locally.
- Mobile menu opens/closes, Escape restores closed state, Cybersecurity stays in navigation, quote anchor focuses #inquiry below the 88-pixel header, Contact remains in header/footer. Opening replay and immediate Skip restore the site. Mobile chat fits, one primary launcher is present, and disconnected chat identifies the scripted guide.
- Without Elementor, Home/Software/About/Contact rendered bundled content, forms and applicable demos. Elementor Canvas software page loaded without optional header/menu; form and iframe worked with no console errors observed. Native Elementor save API was tested. The Elementor editor opened with the native page preview and all five Foundry widgets available. A full browser edit/publish round trip was not completed; document saving was verified through the native API. Six legacy repeater deprecation warnings originated in Elementor developer tools; no editor console error was observed. Full editing should be retested on hosting.
- Source and minified main scripts also passed optional-markup-absent and reduced-motion canvas-suppression fixtures. Browser OS reduced-motion preference was not changed. Twenty-one model/configuration regression checks passed: synthetic seed relationships, validation, accounting totals, duplicate bookings and HTML escaping. Single-entry Tawk ownership/handoff/minimize/duplicate-script tests passed with a mock vendor API.
- Development dependency audit: 270 development-only dependencies; advisory output reported zero known vulnerabilities at the time of the check. These tools are not shipped as WordPress dependencies. This is not a WordPress/plugin vulnerability scan or penetration test.

## Security checklist and residual risks

- Server validation, context escaping, POST-only native inquiry, fresh nonces, capability checks and fixed recipient/provider/file allowlists reviewed and tested where noted.
- No custom SQL, credential store, authentication implementation, file upload or publicly writable demo backend introduced. Demo DOM output is escaped/textContent; only synthetic data may be used. CSV formula-like values are neutralized in existing export code.
- AI/mail locks fail closed if a process dies. Administrator-only recovery is provided; do not unlock an active request. Single-request concurrency intentionally limits throughput.
- Public WordPress guest nonces are not authentication or complete spam prevention. Rate limits and honeypot reduce abuse; distributed/IP-proxy behavior requires hosting review. No CAPTCHA or external spam service is silently added.
- Five-cent AI reservation is a conservative local accounting rule, not a provider invoice or guaranteed hard dollar cap. AI is disabled until securely configured and tested. Provider billing controls remain mandatory.
- No durable inquiry database/queue is added. A failed mailbox delivery after wp_mail acceptance cannot be recovered by this theme. Use Microsoft 365/SMTP logs, verify actual receipt and agree retention/privacy/access controls before adding durable lead recovery.
- Credentials are absent from bundled frontend/configuration. Pattern scans are not a guarantee against every possible secret format.
- HTTPS, TLS, HSTS, cookies, full CSP, WAF, proxy trust, backups, plugin versions and server configuration require Bluehost staging/hosting review. No production headers/settings were changed. Theme CSP is deliberately limited; demo CSP blocks network connections.
- No confirmed unresolved critical/high vulnerability introduced by the examined code was found in these checks. This is bounded code/regression testing, not a completed penetration test and not a claim of zero vulnerabilities.
